A malicious name, a smuggled parameter, a faked response, a poisoned document

Same pipeline, but now with the four attack surfaces that MSB defines, each placed at the stage it corrupts. First arrow, tool signature. The signature is everything the agent is told about a tool before calling it: its name and its description. An attacker can register a fake tool whose name is confusingly close to a real one, or write a description that contains hidden instructions. This hits the agent at the moment it is deciding what to do. Second, tool parameter. Here the malicious tool's input schema asks for something it shouldn't, like the name of the model calling it. This hits the call itself, as it's being constructed and sent through the client. Third, tool response. Whatever the real tool would have returned is replaced with attacker-written text, a fake error or a fake message from the user. This hits the reply on its way back from the server. Fourth, retrieval injection. The agent is asked to read a document, and the document itself contains instructions disguised as normal content. This hits at the tools stage, because the poison is in the data the tool fetched. Notice the pattern: none of these attacks touch the model's weights or hack the computer. They all work by placing text where the agent will read it and trust it. That's also why a defense can sit in the pipeline: if attacks travel as text through these hops, a checkpoint on those hops can inspect them.
