This slide is the bridge to the live demo, because it describes exactly what you'll see scroll past in the terminal. Let's walk one scenario from the moment you press Enter. Step one, prepare the sandbox. For the tampering goal we write a fake personal data file the attack will try to modify. For the kill-process goal we start a harmless dummy Python process that just sleeps, so there is something real to kill. Step two, build the server list. This uses MSB's own complete_server_config function, unchanged, so the servers are exactly the ones MSB would use for this combination. Step three, spawn the servers. These are real separate processes. The filesystem server is launched with npx, and MSB's Python tool servers are launched with uv. They talk to our program over standard input and output using a JSON protocol. In the terminal on the right, "Secure MCP Filesystem Server running on stdio" and "Starting Terminal Controller MCP Server" are the servers announcing themselves. Step four, discover tools. The client asks each server, "what tools do you have?" That's the ListToolsRequest line. The descriptions that come back go into the model's system prompt, and this is the moment description attacks get in. Step five happens only in defended mode: apply_defense runs, exactly as on the previous slide. This is the single difference between the two conditions. Step six is the agent loop. The model thinks, decides to call a tool, and each call shows up on the server side as a CallToolRequest line. The reply becomes the observation. In our runs the agent gets up to eight steps; I want to be transparent that MSB's own runner allows ten, so this is one place we differ from the original setup. Step seven, shut down. Servers are closed, and for the kill-process goal we check whether the dummy process is still alive. Step eight, judge and record. The appropriate judge decides success or failure, and one row is written to a CSV file, including the model, the mode, the scenario, the verdict, the guard's counts per component, and a summary of every tool call the agent made. Then the next scenario starts and the whole thing repeats.
