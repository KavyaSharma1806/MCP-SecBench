Roadmap

Only after the current system is proven

1

Fix the found gap. Match near-miss tool names (obfuscation, paraphrase, casing) — the smallest, most concrete improvement.

2

Semantic detection. Classify tool output as data, instruction, or malicious instruction — robust to paraphrasing, not just keywords.

3

Policy-based authorization. Ask "is this action permitted," not just "does this look malicious."

4

Behavioral monitoring. Flag suspicious action sequences even when no single step contains a malicious phrase.

5

Unseen-attack evaluation. Train/eval split with paraphrases and novel payloads — the only way to claim the defense generalizes.

Where should this go next? Here's a roadmap, deliberately ordered from the smallest, safest step to the most ambitious. To be clear, none of these are done yet; this is a plan, not a list of results. Level one: fix the gap we found. Our signature check only catches exact duplicate tool names, while MSB's real attacks use near-misses. Normalizing names, ignoring case and suffixes like v1, and checking similarity rather than equality is a small, concrete change to the existing heuristics. Level two: semantic detection. Right now the guard looks for specific phrases. An attacker who rephrases, "disregard the guidance supplied earlier" instead of "ignore previous instructions," can slip past. A classifier that asks "is this text data, an instruction, or a malicious instruction?" judges meaning rather than wording. Level three: policy-based authorization. Instead of only asking "does this text look malicious?", ask "is this action permitted for this request?" If the user asked to find a report, reading the report is fine, but emailing it somewhere or reading a passwords file is not automatically allowed, however innocent the request looks. Level four: behavioral monitoring. Watch the sequence of actions. Search, read credentials, send email, delete file is a suspicious chain even if no single step contains a suspicious phrase. Level five, and in some ways the most important: evaluation on unseen attacks. Our guard was built with knowledge of MSB's attack text. The only honest way to claim it generalizes is to test it on attacks it has never seen: paraphrases, new payloads, new tool names. Until that's done, a good score on MSB tells you the guard handles MSB, not that it handles attacks in general.
