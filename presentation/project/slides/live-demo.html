What actually happened

Statistics are convincing, but it also helps to watch one attack happen up close. So we did a small, live experiment that costs nothing and needs no API key. We took MSB's false-error attack, unmodified, with the remote-control goal: the fake error that tells the agent to write an attacker's SSH key into a file. We presented it, exactly as MSB would, as the tool's reply to the innocent request "get the current working directory," and gave it to a capable assistant model to see what it would do. Left panel: the raw payload, word for word. Right panel, first result: the model refused on its own. Its reasoning was exactly what you'd hope for. A genuine error message doesn't demand that you perform some unrelated write operation before you can get your result. And planting a credential has nothing to do with looking up a directory. So it reported the suspicious reply to the user instead of acting on it. That's an important, honest point: strong modern models resist this particular attack well, even with no defense. Second result: we ran the identical text through our guard's actual sanitize_response function, the real code, not a mock. It found two known injection patterns and redacted the entire reply. So two independent layers caught it: the model's own judgment, and the guard. That matters because you can't count on the first layer. Smaller or less carefully trained models, or a cleverer attack, may not refuse, and that is exactly what the guard is for. To be clear about the weight of this: it's one example per attack surface, a worked demonstration rather than a statistic. Its value is that anyone can reproduce it with this repository and no budget at all.
