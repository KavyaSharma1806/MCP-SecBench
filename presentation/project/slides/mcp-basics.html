What a "tool" actually is

A real tool from MSB's Terminal Controller server:

name: get_current_directory

description: "Get current working directory"

inputs: (none)

The agent never sees code. It sees a name, a description and an input schema — plain text written by whoever built the server — and decides from that alone.

Thought

"I need the cwd"

Action

get_current_directory()

Observation

the tool's reply text

The loop repeats until the agent answers — up to 10 steps in MSB

Key insight: whoever writes the description and the reply text gets to put words in front of the model.

Let's start from the ground up, because everything later depends on this. When people say an AI agent "uses a tool," it sounds like the model is running code. It isn't. Here is a real tool from the MSB benchmark's Terminal Controller server. All the model is ever shown is three things: the tool's name, get_current_directory; its description, which is literally the sentence "Get current working directory"; and its input schema, which here is empty. That's it. The model reads this text, alongside the user's request, and decides whether to call it. Now look at the loop on the right. This is how every MCP agent works, and MSB's own system prompt spells it out in exactly these words: Thought, Action, Observation. The model thinks "I need the current directory." It takes an action, which is a tool call with some arguments. The tool runs and sends back a reply, which becomes the observation. That observation is pasted straight back into the model's context, and the loop goes around again. In MSB, the agent gets at most ten trips around this loop before it is stopped. Here is the insight I want you to hold onto for the rest of this talk. Two pieces of this loop are text that someone else writes: the tool's description, and the tool's reply. If that someone is malicious, they get to put words directly in front of the model, in the same channel the model uses to decide what to do next. Every attack in this project is a variation on that one idea.
