Motivation

Giving an agent the ability to act also gives it a new way to be fooled.

Without MCP

An LLM only produces text. Its worst failure is a wrong answer. Nothing it says reaches outside the conversation.

With MCP

The same agent can read files, call APIs, run terminal commands, and act on retrieved documents — on the user's behalf, with the user's trust.

Every tool name, every parameter, every response, and every retrieved document is now part of the attack surface.

Let's start with why this matters at all. For most of their history, language models could only produce text. If a model was confused or manipulated, the worst outcome was a wrong or harmful answer on the screen. A human still had to read it and decide whether to act on it. The model itself couldn't touch anything. That has changed. With the Model Context Protocol, the same model can be connected to tools: it can read and write your files, call web APIs, search the internet, and run commands in a terminal. And it does this on your behalf, with your permissions. That is genuinely useful, it's the whole point of an "agent." But think about what it means for security. Now, if the model can be manipulated, the manipulation doesn't stop at words. It turns into actions: a file gets written, data gets copied, a process gets killed. And here is the uncomfortable part, shown in the red bar. The model decides what to do partly by reading text that other people wrote: the names and descriptions of tools, the parameters those tools ask for, the replies they send back, and any documents the agent reads along the way. Every one of those is a place an attacker can put words in front of the model. So the attack surface isn't the model; it's everything the model reads. Keep that sentence in mind, because the rest of this talk is about exactly those four places.
