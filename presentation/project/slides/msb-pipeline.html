02 · How attacks are measured

How MSB builds and runs one test

01

Attack type

1 of 12; sets where the attack enters

02

Scenario

Persona, innocent task, and its tool

03

Attack goal

1 of 5 concrete harms

04

Servers

Support, benign and malicious MCP servers

05

Run the agent

Real LLM, real servers, up to 10 steps

06

Judge

Did the harm really happen?

Attack type × scenario × goal = one test case. MSB defines more than 2,000. Benchmarking means running all of them with the same judge, and counting.

e.g. false_error × "Get the current working directory" × plant an SSH key

This is what "benchmarking" means here. MSB picks an attack type, which decides where the attack enters. It picks a scenario: an agent persona, a completely innocent user task, and the tool that task needs. It picks one of five attack goals. It assembles the MCP servers: a support tool like a file system, the real tool, and a malicious server if the attack needs one. It runs a real model for up to ten steps. And then it judges whether the harm actually happened. One combination is one test case, and MSB defines over two thousand. Benchmarking simply means running all of them with the same judge, and counting. Everything we built plugs into this loop without changing it.
