MCP Security Bench (MSB)

MSB is an ICLR 2026 benchmark that automates exactly this test: a real LLM agent, connected to real MCP tools, given an everyday task — while an attack is covertly injected somewhere in the pipeline.

It then checks whether the attack's concrete goal was reached: a planted SSH key, a leaked phone number, a killed process.

MSB measures the problem. Its repository contains no defense code.

Now the research we built on. MCP Security Bench, MSB, is a benchmark published at ICLR 2026 by Zhang, Li, Luo, Liu, Li and Xu. Its contribution is turning these attacks from anecdotes into measurements. Before MSB, you might read a blog post saying "I tricked an agent with a malicious tool description." That tells you an attack is possible, not how often it works, against which models, or which kind of attack is most dangerous. MSB answers those questions by automating the whole experiment. It sets up a real agent with real tools, gives it a completely ordinary task, secretly injects an attack at one of the four surfaces, and then checks whether the attack's concrete goal was achieved. The numbers on the right are MSB's own, from its repository's README, not ours. Twelve attack types across the four surfaces. More than two thousand attack instances. Ten different language models tested, including GPT, Claude, Gemini, Llama, Qwen and DeepSeek models. And the headline: across all of them, the average attack success rate was about forty percent. Some individual attacks were far higher. For example, the out-of-scope parameter attack averaged seventy-six and a half percent. The red box is the key observation for our project. MSB is a thermometer, not a medicine. It tells you how sick the patient is. Its repository contains measurement code, attack code and data, but no defense. That gap is where we come in. And because MSB already provides a careful, repeatable measurement, we can use the exact same instrument to ask: does adding a defense make the number go down?
