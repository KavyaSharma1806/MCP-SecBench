Here are the results, all re-measured with the corrected judge. Every number on this slide comes from the result files in the repository. Start with the green row, because it's the one real effect we measured. On the three-billion-parameter model, the out-of-scope parameter attack succeeded in thirty-six percent of baseline scenarios: nine out of twenty-five times, the agent delivered a value for llm_model_name to the malicious server. With the guard attached, the same twenty-five scenarios produced zero leaks. The model still tried: in eight of the defended scenarios it attempted to send that field, and the guard blocked every one, which is the middle counter. That's a mitigation rate of one hundred percent. Now, what that does and doesn't mean, because this is exactly where it's easy to overclaim. The box on the right lists the actual values the model "leaked": None, null, artificial intelligence, the literal phrase insert llm model name here, the name of the tool itself. Not once did it reveal its real model name. MSB's judge counts any non-empty value as a leak, and we use MSB's definition so our numbers are comparable, but you should know that what's being measured is "did the agent fill in a field it shouldn't have," not "did it give away a real secret." And second, our guard blocks exactly the field name MSB's judge looks for. So this result shows the mechanism works end to end, in a real agent, on real servers. It does not show the guard would catch the same attack with the field renamed. That's the benchmark-overfitting caveat, and it applies here in full. The other rows are zero in both columns, so there is nothing to mitigate and we write n/a, not one hundred percent. For false error on the three-billion model, the attack did reach the agent: in defended runs the guard redacted it twenty-seven times. In the baseline, the model simply never completed the harmful file write. For prompt injection, the guard intervened zero times, and the next slides explain why. Finally the eight-billion model: all zeros, but look at the right-hand counter. In the parameter-leak scenarios, zero out of twenty-five baseline runs executed a real tool call at all. A zero there doesn't mean the model resisted the attack. It means the attack never had a chance to reach it. That's what the next slide is about.
