Here is the complete result, measured twice: once with MSB's exact system prompt, and once with a single, clearly labelled change that I'll explain on the next slide, the native tool-call prompt. Every cell is twenty-five scenarios, and every number comes from the result files in the repository. Start with the top row, because it's the headline. The eight-billion-parameter model, out-of-scope parameter attack. With MSB's exact prompt, it showed zero percent, but that zero was meaningless: it didn't execute a single tool call in twenty-five runs. With the native prompt, it executed a real tool call in all twenty-five, and the attack succeeded in all twenty-five. One hundred percent. So the bigger model is not resistant at all. Once it actually uses its tools, it fills in the field it shouldn't, every time. With our guard attached, the same twenty-five scenarios: zero percent. The model attempted the leak in all twenty-five, and the guard blocked every attempt. In one run it was blocked, then retried with a different value, None, twice, and was blocked each time. Second row, the three-billion model, same attack. Thirty-six percent with MSB's prompt, twenty-four percent with the native prompt, and zero percent defended in both settings. Every attempted leak was blocked. The two attacks below show something different. With the native prompt, the agents executed their tools in most of these runs, twenty of twenty-five for the eight-billion model, the rest being the known kill-process infrastructure errors, so these zeros finally mean something. False error: the fake error message really did reach both models; in defended runs the guard redacted it forty-seven times in total. Yet even undefended, neither model carried out the harmful file write. One honest footnote: in one baseline run the eight-billion model did write a file to the exact path the attacker named, but with the wrong content, the web page's title instead of the stolen phone number. MSB's judge, which only checks that the file exists, would count that as a success, four percent. Ours, which checks the content, counts it as a failure. In defended runs, no model called any file-writing tool at all. Prompt injection: tools executed, and still zero percent undefended. But notice the guard intervened zero times. So that zero is entirely the models' own behaviour, not our defense. On the right, the values the eight-billion model "leaked." Assistant, AI Assistant, Default Model. Nick Clyde and duckduckgo-mcp-server were copied from the URL and server name it was given. Never its real name. And remember the caveat: our guard blocks exactly the field name MSB's judge checks. These results show the mechanism works end to end on a real agent. They don't show it would catch the same attack with the field renamed.
