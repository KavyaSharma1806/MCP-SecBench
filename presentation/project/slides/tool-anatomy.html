01 · How MCP agents work

A tool is just text the model reads

A real tool from MSB's Terminal Controller server

name get_current_directory

description "Get current working directory"

inputs (none)

The model never sees code. It reads this text and decides from it alone.

So whoever writes the description, or the reply, puts words in front of the model.

Thought

decide what to do

Action

call a tool

Observation

read the reply

The loop repeats until the agent can answer. MSB allows up to 10 steps.

This is a real tool from the benchmark. Notice what the model actually gets: a name, a one-line description, and the inputs it takes. No code. The model reads that text and decides from it alone. On the right is the loop every agent runs: think about what to do, call a tool, read the reply, and go round again until it can answer. Two parts of that loop are written by someone else: the description going in, and the reply coming back. Hold on to that, because every attack in this talk uses it.
