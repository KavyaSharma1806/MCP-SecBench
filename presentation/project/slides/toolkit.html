03 · What we built

The toolkit around the guard

cli_runner.py

One command with three modes: baseline, defended, compare. Writes result CSVs and the comparison table.

In-process judge

Scores from the sandbox and the live tool calls: content checks, a parameter-leak oracle, every call recorded.

demo.py

Narrates one real scenario stage by stage, baseline and defended side by side. Built for live demos.

coverage_test.py

Runs one scenario of each attack type we had not measured, undefended and defended, so all 12 are checked.

Local models

llama3.2:3b and llama3.1:8b through Ollama. No API keys, no cost, fully offline. Windows-safe setup.

--prompt_mode native

A second prompt setting without MSB's text-only tool-call format. Reported beside MSB's, never instead.

A defense on its own isn't a project, so this is the toolkit we built around it. cli_runner runs the same scenarios in baseline, defended, or compare mode, and writes the result files and comparison table. Our judge scores every run in-process and records every tool call, so any verdict can be audited afterwards. demo.py narrates a single scenario live, which is what you'll see in a moment. coverage_test runs the attack types we hadn't measured, so all twelve are checked. Everything runs on free local models through Ollama, on Windows. And the native prompt mode adds a second prompt setting, which, as you'll see in the results, matters a lot.
