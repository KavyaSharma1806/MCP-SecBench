Before we look inside our guard, let's reason about where a defense should live, because the answer follows directly from everything we've learned so far. We said every attack is text crossing one of these hops. So ask: which single hop sees all four kinds of attack traffic? Look at the hop between the MCP client and the MCP server, highlighted in green. Going outward, toward the server, it carries every tool call the agent makes, including the parameters, so a parameter attack has to cross it. Coming back, toward the agent, it carries the tool descriptions the server advertises, every tool reply, and every document a tool fetches. Signature attacks, response attacks and retrieval attacks all arrive across it. You could put a defense inside the model, by retraining it. That's powerful but expensive, and you'd have to redo it for every model. You could put it inside each tool server, but the whole problem is that you don't control the malicious server. The client-server hop is the one place you control that every attack must pass through. One caveat we'll come back to. In a real deployment, a malicious tool description comes from the server, so it crosses this hop. But MSB simulates its prompt-injection attack differently: it inserts the injected text inside the agent process, straight into the system prompt. In the benchmark, that attack never crosses this hop at all, which is exactly why our guard turns out to miss it. So that's where we put it. Watch what happens on the next slide.
